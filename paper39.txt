## 摘要

本文是一组初步实验的整理：给小型 Transformer 的每一层加一个"门"，尝试让模型按内容决定"这一层做变换"还是"放行（不变换）"。

统一命名：门开 = 放行（不变换），门关 = 计算（正常变换）。

实验用两种规模：6 层、宽 128（约 1.2M 参数）；24 层、宽 128（约 4.7M 参数）；字符级 tinyshakespeare。

主要观察（全部单种子，带噪声，只作参考）：

1. 硬预算会退化：每个 token 最多算 k 层时，最优解是"固定用前 k 层"，所有 token 一样，门失去"按内容选择"的意义。
2. 软代价直接加梯度会崩：把"计算层数"的代价直接加到损失上，门全部关闭（PPL 从 6.2 崩到 8.4~12.3）。
3. 拉格朗日乘子可行：用自适应 λ 把平均计算层数压到目标附近，6 层模型目标 2~3 层时 PPL 与全层基线持平（噪声内）；24 层模型平均只用 5.3~5.4 层，PPL 与 24 层全层基线持平（噪声内）。
4. 结构有规律：24 层门控模型里，第 0 层几乎必算（计算率 1.00），少数层是"热层"（L1≈0.51、L9≈0.42、L20≈0.33、L22≈0.59），其余层大部分 token 都跳过；最后一个层几乎不用（L23≈0.04）。每个 token 的计算层数分布 1~15 层，集中在 3~8 层。
5. 负结果：位置门在预算充足时全部打开（无结构）；预算紧张时出现的"跳过开头"是分配假象；"跳过时带变换"比恒等放行更差。

所有数字为单种子或 3 种子，运行间波动约 ±0.1~0.2（PPL）。本文不声称对大模型成立，也不声称这些是"组合律"的证明，只是一组工程观察。

## 一、问题

框架里"判定 J"是"有备选时一次通过的选择"。工程上最简单的实现是：每层每 token 一个 0/1 门，决定这一层是否参与计算。由此产生三个问题：

1. 门能不能学会"按内容"选择，而不是退化成固定模式？
2. 用什么约束能让"少算"与"质量"平衡？
3. 门控后的模型，结构长什么样（哪些层被用）？

## 二、方法

### 2.1 模型

- 小 Transformer：6 层/24 层，宽 128，4 头，FFN 512；字符级词表（63）；上下文 128。
- 数据：tinyshakespeare，90% 训练 / 10% 验证；训练 2500 步，batch 8，Adam，lr 1e-3。
- 设备：DirectML GPU。

### 2.2 门与三种约束

门：g = sigmoid(MLP(h))，逐层逐 token。

- 硬预算：每 token 最多算 k 层；超过则强制放行。
- 软代价：损失 += λ · 平均计算层数（用软概率保证梯度）。
- 拉格朗日：λ 自适应：λ ← λ + η(平均计算层数 − 目标)，压到目标附近。

前向：计算时 h ← block(h)；放行时 h 不变（恒等）。硬门用 straight-through 估计训练。

## 三、结果

> 所有对照都给出"无门全层基线"的 PPL。

### 3.1 硬预算：退化为"固定前 k 层"

6 层模型，E0 = 每 token 最多计算层数：

| 设置 | PPL | 平均计算层数 |
|---|---|---|
| 无门全层基线 | 6.232 | 6.00 |
| E0=3 | 6.217 | 3.00 |
| E0=2 | 6.166 | 2.00 |
| E0=1 | 6.257 | 1.00 |

3 种子对照（全层 vs E0=2）：全层均值 6.103，E0=2 均值 6.062，2/3 个种子更好——差异在噪声内。

但分析门的逐层计算率发现：所有 token 的计算层数完全相同，学到的模式是"固定前 k 层"（例如 E0=3 时 L0-L2 计算率 1.00、L3-L5 为 0）。结论：硬预算下"按内容分配"没有意义，模型可以干脆训练成一个浅模型。

### 3.2 软代价 + STE：崩塌

6 层模型，损失 = 语言建模 + λ·平均计算层数（软概率，梯度可传）：

| λ | PPL | 平均计算层数 |
|---|---|---|
| 0.5 | 8.424 | 0.63 |
| 1.0 | 12.258 | 0.06 |

门全部关闭（几乎全放行）。原因：代价梯度与 STE 结合后，关闭所有门是最省代价的局部最优。结论：这个形式的软代价不可用。

### 3.3 拉格朗日：可行

6 层模型，目标平均层数 2/3/4：

| 设置 | PPL | 平均计算层数 |
|---|---|---|
| 无门全层基线 | 6.232 | 6.00 |
| 目标 2 层 | 5.971 | 2.06 |
| 目标 3 层 | 5.961 | 3.06 |
| 目标 4 层 | 6.186 | 3.50 |

24 层模型：

| 设置 | PPL | 平均计算层数 |
|---|---|---|
| 无门全层基线 | 5.705 | 24.00 |
| 目标 6 层 | 6.114 | 6.01 |
| 目标 12 层 | 5.705 | 5.39（λ=0，未触发） |
| 目标 18 层 | 5.852 | 7.81 |

观察：目标 12 那组自适应 λ 始终为 0，门自由选择只算 5.39 层，PPL 与 24 层基线相同（同配置两次运行分别为 5.705 与 5.876，差 0.17，属运行噪声）。⇒ 在这个任务上，24 层模型实际只需要约 5.3~5.4 层。

### 3.4 24 层门控模型的结构

单次结构分析（目标 12，自由门控）：PPL 5.876，平均计算层数 5.33 / 24。

各层计算率：


L00 1.00   L01 0.51   L02 0.07   L03 0.18   L04 0.12   L05 0.19
L06 0.10   L07 0.27   L08 0.10   L09 0.42   L10 0.21   L11 0.05
L12 0.04   L13 0.12   L14 0.24   L15 0.08   L16 0.05   L17 0.11
L18 0.25   L19 0.19   L20 0.33   L21 0.08   L22 0.59   L23 0.04


- 第 0 层必算；少数"热层"（L1、L9、L20、L22）常用；其余层大多数 token 跳过；最后一层几乎不用。
- 每 token 计算层数分布：1:3、2:118、3:377、4:526、5:468、6:416、7:266、8:169、9:118、10:52、11:29、12:9、13:7、14:1、15:1。
- 计算层数与 token 损失几乎无关（Spearman −0.087）。

### 3.5 负结果

- 位置门：门值只由位置决定。E0=6（预算充足）时几乎全部打开（平均 5.94 层，PPL 5.995 vs 基线 6.232，无省算）；E0=3 时出现"前 20 个位置全跳过"，给足预算后该现象消失 ⇒ 是预算竞争造成的假象，不是结构。
- 跳过时带变换：跳过时 h ← h + 0.1·T(h)（或 h ← T(h)），PPL 6.122 / 6.262，都比恒等放行（6.038）差。
- 每门资源池（5 层跨层网络，奇偶任务）：每个门一个资源池，按使用与贡献更新，10 个门里 5 个被"饿死"，准确率 0.866（对照：全层约 0.87~0.91）。

## 四、讨论

1. 约束形式决定门的行为：硬预算 → 固定浅层；软代价+STE → 全关；拉格朗日 → 可控且分化。
2. 深度冗余明显：6 层任务上 2~3 层、24 层任务上 5.3~5.4 层，PPL 与全层在噪声内持平。
3. 结构的规律：L0 必算、少数热层、每 token 深度 1~15 层；但深度与 token 难度无关，分配依据尚不清楚。
4. 测量噪声：同配置两次运行 PPL 差约 0.17，跨种子差约 0.2；本文所有"持平/略好"都在这个噪声带内，不能精确比较。

## 五、局限

第一，单种子为主，只有个别设置跑了 3 种子。

第二，模型小（1.2M~4.7M 参数）、字符级、语料单一（tinyshakespeare）。

第三，只统计"计算层数"，没有测真实 FLOPs、延迟与显存。

第四，拉格朗日目标在 12/18 层设置未触发（目标未绑定），语义不纯。

第五，结构分析是单次运行的快照，"热层"是否稳定未验证。

第六，与 MoD/early-exit 等工作的对比未做同设置实验。

## 六、与框架的关系（保守）

- 门 = 判定 J 的一种工程实现；放行/计算 = 组合律的一种选择。
- 本文只报告"怎么让门工作、门会长成什么样"，不声称门控证明了组合律、也不声称这些结论能外推到真实大模型。
- 若方向成立，它属于执行器工程（P 侧），与"生命"无关。
