# 散论：层是看法

> 何淇 · 与 DeepSeek（AI）协作
> 数字生命系列 · 散论
> 日期：2026-11-26
> 说明：散论不是论文；这里提出一个看深层网络的角度，不报告新实验。标注沿用系列习惯。

---

## 一、一句话

[判断] 可以把每一层理解成对同一份信息的一种"看法"：它不生产新信息，只是把信息重排成另一种形式，让某个目标更容易达成。

[事实] 这个说法和我们的"信息不增"一致：加工不会创造新的可区分；层做得再多，信息量也不会超过输入加先验。

## 二、看法是什么意思

[判断] 所谓"看法"，就是"用什么方式排列同一份信息"：

plain
· 原始信息：输入的 token/像素（一份）
· 第 1 层：提取局部关系 → 一种排法（看法 1）
· 第 2 层：在"原始 + 看法 1"上，提取更长的依赖 → 看法 2
· 第 3 层：在"原始 + 看法 1 + 看法 2"上 → 看法 3
→ 每层加一种看法，而不是加"更多信息"


[判断] 好处在于：同一份信息，换个排法，难度就变了。

plain
· 排得对：目标变成"简单函数"（局部、线性、可分）
· 排得不对：目标仍是"复杂函数"（需要更多层/更宽/更多数据）
→ 所以：好的看法 = 让后续处理更省力，而不是让信息变多


## 三、为什么残差是必要的

[判断] 如果每层都"替换"上一层，那么"原始信息"和"早期看法"都会丢；后层只能看到被压缩过的结果。

[事实] 残差让每个位置上的向量变成累积：h_l = h_0 + Δ_1 + … + Δ_l。

[判断] 这正好给了后层两种访问：

plain
· 直接看原始信息（h_0 那部分还在）
· 看前面各层的加工结果（Δ 累积）
→ 所以：每一层都可以"在原始上重新提取"，也可以"在已有看法上继续加工"


[判断] 这是深层网络能"同时用句法和语义"的原因：句法是低层看法，语义是高层看法，两者都在同一条流里。

## 四、这解释了三个现象

plain
1) 深度 = 能同时维持的"看法数"
   · 每层一种看法；层多 = 看法多
   · 但看法会混在一起（累加）→ 需要选择机制（注意力/门控）

2) 宽度 = 能放得下多少种看法
   · 每种看法要占通道/维度
   · 我们实验测到"宽度是瓶颈、头数无关"——和这个解释一致：
     宽度决定"能同时装几种看法"，头数只是"怎么切"。

3) 加模块 = 加一种看法（或加一个看法来源）
   · 加性生长（旧能力不退化）对应：新看法加进去，旧看法还在
   · 冻结旧模块 = 固定已有看法，只学新看法


## 五、由此得到的判断

[判断] 深度不是"想得更久"，而是"看得更多种"。

plain
· 迭代（反复算同一个算子）追求收敛 → 有"过冲/饱和"问题
· 深层（堆不同的看法）追求表达 → 是"视角的组合"，不追求收敛
→ 两者不是一回事：深层网络不是"想得久"，是"看法多"


[判断] "更好的看法"不是玄学，可以量化：

plain
· 同一份信息，好的看法让目标函数更简单
  · 更局部、更线性、更低阶 → 所需层数/数据更少
· 所以：架构设计 = 选择"哪几种看法优先"
  · 卷积：平移不变的局部看法
  · 注意力：内容相关的全局看法
  · 归一化：尺度看法
→ 设计归纳偏置 = 设计"看法的先验顺序"


## 六、边界

plain
· 本文不声称"层就是看法"是唯一解释（只是有用的抽象）
· 不能说明"为什么是这种看法更好"（那需要具体任务的数学）
· 看法会互相混合：残差累加后难以分离（可解释性困难）
· 信息上限不变：再好的看法也不能变出数据里没有的信息
→ 所以：这是"效率视角"，不是"能力来源"


## 七、和系列的关系

plain
· 论文-59：信息不增（加工不产生新可区分）
· 论文-48：结构 = 可压缩的部分
· 本散论：层 = 重排（换排法，不换信息量）
→ 三者是一条线：信息有限 → 结构是可压缩部分 → 层的任务是"排得更好"



## 八、从"看法"到"模块化结构"

[判断] 如果每一层是"一种看法"，那么"多个模块 + 融合层"就是"多个视角 + 一个统一判断"。这就是本系列里模块化设想的来源。

plain
                 顶层（统一表示/判断）— 最宽
                   ▲              ▲
              ┌────┴────┐    ┌────┴────┐
              │ 中层 A  │    │ 中层 B  │    ← 融合（更宽）
              └────┬────┘    └────┬────┘
     ┌─────────────┼───────────────┼─────────────┐
     ▼             ▼               ▼             ▼
 底层模块1      底层模块2       底层模块3      底层模块4(新增)
     ▲             ▲               ▲             ▲
 数据源:文字   数据源:图像     数据源:声音    数据源:其它

  · 竖向直通线 = 残差：原始信息 + 各层增量，全部保留 → 信息不丢
  · 底层→中层箭头 = 注意力整合：决定"信哪个源、信多少"
  · 新增模块 = 零初始化接入 + 旧模块冻结 → 旧能力不掉
  · 修剪 = 门控≈0 / 消融无效 / 冗余 → 剪掉（与生长对称）


[判断] 这个结构的好处是"统一"：加源、判断、修剪用同一套机制。

plain
· 加源：新数据源 = 新底层模块；上层注意力自动能读
· 判断：融合层的注意力权重 = "这个输入该信哪个源"（学出来的）
· 修剪：权重长期≈0 的模块 → 剪掉
→ "自我"可以放在顶层：它读所有源 + 记忆，做统一判断与调制


[看法] 两个时间尺度：

plain
· 快：记忆/看板刷新（冗余数据 → 只更新记忆，不改结构）
· 慢：结构生长（真正新的东西 → 加模块，罕见）
→ 判据是"预测得了吗"：冗余 → 记忆；惊讶 → 结构


## 九、开放问题：怎样的验证器才算"好"

[判断] 前面所有机制（加模块、修剪、停机、路由、回滚）都依赖一个东西：能判断"什么是有用/对"的信号。这个信号就是验证器。

plain
· 代码：跑测试；数学：证明检查；棋：胜负
  → 这些领域能准确验证，因为规则完整、后果可算
· 开放世界：没有准确验证器
  → 只能靠代理信号：预测误差、一致性、人工审核
  → 代理可以被钻空子（越练越自信 ≠ 越对）


[推测] "验证器"和"内化世界"是同一个度量：

plain
· 验证 = 预测后果；能预测多少后果 = 内化了多少世界
· 完美验证器 ⇔ 完全内化
→ 没有通用验证器，约等于"世界没有被完全内化"
  这和"世界不可算、观测不全"是同一件事


[判断] 所以"怎么得到一个好的验证器"是开放问题：

plain
· 局部验证器：可造（代码/数学/仿真/领域规则）
· 通用验证器：没有（需要内化整个世界）
· 折中路线：
  · 分领域拼装验证器（每个可内化的子世界一个）
  · 用预测误差/一致性当代理（不保证正确，只能保证"新/稳"）
  · 人在回路（最终判据还是人）
→ 目前没有"通用验证器"的构造方法；这是开放问题，也是"通用智能"的同一个问题的另一面


---

> 一句话：层不生产信息，只换看法；好的看法让目标变简单；深度是看法数，宽度是容纳量——这就是深层网络在做的事。
