## 摘要

前两篇执行器工程用的是从头训练的小字符模型（约 1.2M 参数）。本篇把同一套方法搬到预训练的 GPT-2（124M）上，在单卡 V100 上做三组对照，并实现真实稀疏执行测 FLOPs 与墙钟。

主要观察：

1. 冻结主干 + 门 + 拉格朗日会把层数压到约 5 层，但质量崩溃（PPL 1332）：预训练模型没有被训练成"能容忍跳层"。
2. 主干 + 门共同训练（微调 + 拉格朗日，目标 6/12 层）可行：PPL 32.19，平均 5.96/12 层；同轮 plain 全层微调 PPL 58.83（小数据过拟合，单种子，不作"门控更优"声称）。
3. 真实稀疏执行与稠密门控逐元素等价：PPL 32.188 对 32.188；FLOPs 由 0.89 降至 0.50 GFLOPs（约省 43%）。
4. 但 GPU 墙钟没有变快（11.9 ms → 20.5 ms，batch=1）：gather/scatter 与索引开销吃掉了收益；真实加速需要固定容量/kernel 优化（MoD 式）。

## 一、设置

- 模型：GPT-2（124M，12 层，d=768，FFN=3072），从预训练权重出发。
- 数据：tinyshakespeare（约 1MB），BPE 词表，上下文 128，batch 8。
- 门：每层一个 σ(W·h + b)，对 token 的输出写回做 0/1 决策；拉格朗日 λ 自适应，把平均层数压到目标 6。
- 硬件：阿里云 PAI-DSW，单卡 V100-SXM2-16GB；训练 1500 步/组。
- 三组：plain（全层微调）、frozen_gate（冻结主干，只训门）、joint_gate（主干 + 门共同训练）。

## 二、结果：三组对照

| 组 | PPL | 平均层数 |
|---|---|---|
| plain（全 12 层微调） | 58.83 | 12 |
| frozen_gate（冻结 + 门 + 拉格朗日） | 1332.12 | 5.20 |
| joint_gate（共同训练 + 门 + 拉格朗日） | 32.19 | 5.96 |

解读（保守）：

- frozen_gate 崩溃说明：预训练权重默认每一层都被用到；仅在外部压层数而不让主干适应，会直接破坏计算。
- joint_gate 能用约一半层数维持语言建模质量；本轮其 PPL 低于 plain，但这是小数据过拟合 + 门控正则化的混合结果，不作为"门控更优"的证据。
- 单种子，且小数据上 plain 的 PPL 本身偏高，组间差值应视为同量级。

## 三、学习到的层使用模式

joint_gate 一次训练的每层活跃率（验证集，按 token 平均）：


L0  0.95
L1  0.05
L2  0.67
L3  0.62
L4  0.53
L5  0.50
L6  0.47
L7  0.60
L8  0.60
L9  0.43
L10 0.87
L11 0.16


观察（推测）：

- 第一层几乎必算；第二层几乎不用；第 10 层很常用、最后一层用得少。
- 这不是单调的"前段必算、后段少算"，而是任务/数据相关的不规则模式。
- 与从零训练的小模型相比，预训练模型的层使用模式更"打补丁"，也解释了为什么冻结主干时一跳就崩。

## 四、真实稀疏执行

实现：保留全部 K/V（注意力记忆），只计算被选中 token 的 Q、注意力输出行与 MLP；因果掩码按真实位置。加载微调后的主干与门后评测。

| 指标 | dense 门控 | 查询端稀疏 |
|---|---|---|
| PPL | 32.188 | 32.188 |
| 每层 FLOPs（估算） | 0.89 GFLOPs | 0.50 GFLOPs（约 −43%） |
| GPU 墙钟/每 batch（batch=1） | 11.9 ms | 20.5 ms |

- PPL 完全一致：说明稀疏实现与稠密门控逐元素等价，不是近似。
- FLOPs 约省 43%，与从头训练的小模型结果（约 43%）同量级。
- GPU 墙钟反而变慢：batch=1 时索引/gather/scatter 开销占主导。这说明"FLOPs 省"不自动等于"时间省"；要拿到真实加速，需要容量固定的批量路由（MoD 式）或定制 kernel。

## 五、局限

- 单种子、单卡、小语料（1MB）；plain 的 PPL 受过拟合影响显著。
- 目标层数是人工设定的 6/12，不是学出来的最优值；未跑目标 3 层等更低预算。
- 稀疏执行的墙钟只在 batch=1 下测过，未测大 batch/吞吐。
- 未与 MoD 等容量路由方法做同设置对比。

## 六、结论（观察，不是新方法）


· 在预训练 GPT-2 上，"主干 + 门共同训练 + 拉格朗日"
  可以用约一半层数维持语言建模质量（本轮 PPL 不劣于全层微调）；
· 冻结主干直接压层数会崩溃，说明共同训练是必要条件；
· 查询端稀疏执行可在不改变输出（PPL 完全相同）的前提下
  省约 43% 的 FLOPs，但在 batch=1 的 GPU 上没有时间收益；
· 方法机制与 MoD/早退/条件计算同属一类，本篇不声称提出新方法。
